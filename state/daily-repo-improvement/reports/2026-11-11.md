## Lead finding: committed database credentials in `comicogs_new` (private repo)

`origin/main` tracks `.env.production` and `.env.staging` (plus `.env.backup`, `.env.docker.production`, `.env.docker.local`, `.env.production.backup`, `temp_secret.txt`). Both `.env.production` and `.env.staging` contain a live-looking `DATABASE_URL` / `DATABASE_URL_STAGING` connection string with embedded username:password. The repo's own `.gitignore` already has rules that should exclude `.env.*` (`.env`, `.env.*`, with templates excepted) — these files were committed before that rule existed and git doesn't retroactively untrack them, so they're still in history and in the current tree.

I did not touch this (never touch secrets, per hard rules) and skipped `comicogs_new` for every other change this run out of caution, same as the fleet's "open security advisory" skip rule. **Recommended next steps for you:** rotate the DB credentials in both files immediately (repo is private but has presumably been cloned to this Mac and possibly elsewhere), then either `git rm --cached` the tracked `.env*`/`temp_secret.txt` files going forward or scrub them from history with `git filter-repo`/BFG if the credentials can't be rotated cleanly. Also worth a look: the repo root has ~6 `*-backup` directories and a dozen `*_SUMMARY.md`/`*_PLAN.md` files that look like they should move into `docs/` or be deleted.
