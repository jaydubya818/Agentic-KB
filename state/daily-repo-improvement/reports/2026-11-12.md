## Self-caught mistake avoided (worth flagging explicitly)
My own mechanical scan script used a combined zsh glob (`ls LICENSE* LICENCE*`) to check for a LICENSE file. zsh aborts the **entire** command with "no matches found" if *any* one glob in the line fails to match — so every repo's LICENSE check silently came back empty, including repos that do have a LICENSE file. This produced a false lead: Agentic-KB, mnemonic-kb, SellerFi, MissionControl, and MissionControlEnterprise all have a README "## License" section naming MIT, and the (broken) scan said none of them had a LICENSE file — which looked like a textbook Tier A "missing LICENSE when repo states one" fix across 5 repos. Before touching anything I re-ran a corrected per-pattern check and confirmed all 5 already have a root `LICENSE` file; the apparent gap was entirely my own script bug, not a repo defect. No commits were made on this basis. The only repo that actually lacks both a LICENSE file and a clear stated license is twinz, whose README says "License: TBD" — not a stated license, so not the Tier A case either.
