## Headline finding: twinz has an unrotated leaked credential, open 2 months

`twinz/docs/NIGHTLY-BACKLOG.md` has carried an **Open** item since 2026-09-01:
a live Vercel API token (`.mcp.json` → `mcpServers.vercel.env.VERCEL_TOKEN`) was
committed in `bc80237` (2026-01-21) and only redacted at HEAD on 2026-09-01.
Redacting HEAD does not remove it from git history or existing clones — it is
still retrievable by anyone with read access to the repo. The backlog's own
assessment: an attacker with that token has full Vercel account control,
including read access to every project's `DATABASE_URL`, `AUTH_SECRET`, and
`OPENAI_API_KEY` env vars, plus deploy/delete rights.

This remediation is out of scope for every automated job (revoking a live
credential at vercel.com/account/tokens is a human action, and this job's hard
rules forbid touching auth/secrets files) and it has sat open for ~2 months
with no sign Jay has revoked it. **Recommend: rotate the token now.**

Two related, lower-severity items on the same repo, also open since 2026-09-01
and untouched since:

  `.gitignore` rule — `.mcp.json.example` already exists as the template).
  Not done by this job: it changes what a fresh clone gets, which the backlog
  itself flags as "should be a deliberate call," and it doesn't help until the
  token above is rotated anyway.
