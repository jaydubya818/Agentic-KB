# Harrison Chase — Managed Agents Thesis

## Source
- Raw capture: `raw/framework-docs/x-twitter-2085780032031760694.md`
- Source URL: https://x.com/hwchase17/status/2085780032031760694
- Source quality: first-party LangChain founder/product thesis for Managed Deep Agents; strong for LangChain positioning, weaker as neutral market evidence.

## TL;DR
Harrison Chase argues that production agent building is splitting into three layers — business logic, harness, and infrastructure — and that managed agents package the harness plus production runtime so builders can focus on context, tools, and instructions.

## Key Points
1. The source narrates agent-building eras: early AI frameworks/apps, mature control frameworks, model-powered agents running in tool loops, then agent harnesses such as Claude Code, Pi, and Deep Agents.
2. Two learnings drove the managed-agent thesis: production primitives such as durable execution and sandboxes, and emerging behavior-definition standards such as AGENTS.md, MCP, and skills.
3. Chase defines three parts of an agent system: custom business logic; the harness; and production infrastructure.
4. The operational infrastructure checklist includes reliable/resumable runtime, UX/event streaming, sandboxing, context management, evaluation, memory, and auth/identity.
5. Fleet, Claude Managed Agents, Vercel Eve, and Managed Deep Agents are positioned as examples or adjacent entries in this managed-agent category.
6. Managed Deep Agents is described as Deep Agents plus LangSmith-hosted infrastructure: Deployments, Agent Server/Channels, Sandboxes, Context Hub, Harbor evals, memory, and AuthN.
7. File-backed agent definitions are a recurring design point: Fleet represented agents as filesystem files; Managed Deep Agents also represents agents as files while allowing custom middleware and tools as code.
